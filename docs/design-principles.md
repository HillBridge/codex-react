# 项目中的编程思想

本文梳理当前项目体现的编程思想，以及它们在代码中的落点。

## 两点校正

- Hooks 不等于函数式编程。Hooks 是 React 为函数组件提供的状态和副作用机制，内部靠可变状态实现。项目中真正的函数式风格体现在数据驱动配置和纯函数（如 `entries` 里的展示规则）。
- 测试和门禁齐全，不等于测试先行。测试文件与切片同置，提交钩子跑测试，符合 TDD 的工程环境，但先写测试再写实现的顺序无法从代码中确认。

## 思想与落点

| 思想                         | 项目中的体现                                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 声明式 / 数据驱动配置        | `features/orders/orderListConfig.tsx` 用列定义和筛选字段数组描述表格，通用的 `DataTable`、`TableFilter` 负责渲染。新增一列只需改数据。 |
| 关注点分离 / 单一职责        | `shared/api/request.ts` 只管请求和响应校验，`sessionExpiry.ts` 只管广播，路由和缓存的反应由上层决定。                                  |
| 发布订阅（观察者模式）       | `sessionExpiry.ts` 通过 `window` 事件广播 401，请求层不依赖路由和缓存。`onSessionExpired` 返回取消订阅函数，供 effect 清理。           |
| 依赖倒置 / 依赖方向约束      | FSD 的"只依赖更低层"由 ESLint 强制，是架构层面的依赖规则，不靠自觉。                                                                   |
| 封装与信息隐藏               | 每个切片的 `index.ts` 是公共出口，只导出外部要用的成员，内部文件不允许被深层引用。                                                     |
| 适配器 / 外观                | `apiRequest` 包装 axios，统一 204 处理、非法 JSON 报错；`ApiError` 把传输层错误转成业务错误。                                          |
| 契约式 / 防御式编程          | 响应体是字符串时主动抛 `INVALID_RESPONSE`，不信任外部输入。                                                                            |
| 键工厂 / 层级命名空间        | `queryKeys.ts` 用层级键加前缀匹配实现批量失效，把"缓存失效范围"变成可组合的数据。                                                      |
| 中间件管道（责任链）         | 后端 `errorHandler → requestId → bodyParser → 路由`，每层只做一件事，错误统一在最外层处理。                                            |
| 单一数据来源                 | 服务端状态只在 React Query，筛选和分页只在 URL，没有第二份拷贝。                                                                       |
| 约束即代码（Policy as Code） | ESLint、Stylelint 令牌约束、Git hooks 把规范变成机器检查。                                                                             |
| 测试隔离 / 环境可重复        | e2e 用独立端口的新后端，每次从初始数据开始，保证确定性。                                                                               |
| 文档先行 / 规格驱动          | `docs/superpowers/specs` 和 `plans` 先写设计与计划，再实施。                                                                           |

## 最值得深入的两点

- 发布订阅：解决了跨层通信不能反向依赖的问题。
- 声明式配置：是这个项目复用性的主要来源。
